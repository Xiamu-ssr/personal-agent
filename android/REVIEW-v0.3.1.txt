Personal Agent Android 0.3.1 本地验收

实现方式
- 输入框不再随主线程 busy 变成停止按钮，忙时照常打字 / 发送；上传期间也允许继续修改文字草稿。
- 用户气泡区分 pending（等待服务端回显）和 queued（排队），排队使用浅色背景、淡文字及右下角「排队中」。
- 以服务端回显顺序为准，下一次新 user 回合按 FIFO 解除一个已确认消息的排队状态；重复 status 不重复解除。也覆盖两个设备的消息竞争及相同文字 / 附件的回显。
- 忙闲仅由 status / hello 决定；turn_end 只提交结果，不强制 idle。新回合重置流式文字、工具提示及当前错误提示。
- 没有 user 事件的 task_result 回合仍正常接收 delta / turn_end，历史 assistant 和简报 card / job.done 继续显示。
- 输入框上方按 reason 显示「豆豆正在处理子任务结果…」「豆豆正在安排定时任务…」或「豆豆正在回复…」。独立「停止回复」按钮只发送 interrupt，不弹窗，也不删除后台任务或队列消息。
- 后台任务单独按 id 维护，与 /api/jobs 的隔离作业分开。hello / state / task.snapshot 替换列表；started 幂等；progress / updated 只更新已知任务；终态 notification / patch 移除对应 id。
- 空 snapshot 清空任务；完成 id 有有限去重记录，防止乱序 started / progress 复活。历史 card 不用于还原运行任务。
- 输入框上方的任务条显示「后台还有 N 个任务在跑」，展开后显示描述、已运行时长和每项停止按钮。任务页的进行中也显示这些后台任务及停止入口。
- 按任务停止发送 {t:"stop_task",id}；按钮禁用并显示「停止中…」。task_stop 成功仅代表控制请求被接受，仍等待 notification 或 snapshot 移除。失败恢复按钮并显示中文原因，支持重试。
- source:schedule 的历史和实时 user 消息都转换为居中灰字，使用 Material Alarm 图标，从「该出「X」了」提取「X时间到了」；普通用户写 [定时] 不会误判。
- 断线立即清除 busy、流式文字、工具提示和运行列表。主动关闭握手会触发重连；新 hello 恢复服务端列表和 busy，清除旧停止状态。请求 generation / task revision 防止迟到 HTTP 响应覆盖新连接或复活已结束任务。
- 版本 0.3.1，versionCode 5。

过程中修复的问题
- 第一次模拟器测试在 debug fixture 清理时调用服务端 WebSocket.cancel 导致 NPE；改用正常关闭握手，已消除。
- 第二次测试 24 / 25 通过，主动关闭后的重连超时；发现生产 Listener 缺少 onClosing 回应。补齐握手及断线处理后，完整测试组通过。
- APK 检查最初用字符串搜索判断 MockWebServer，误命中 OkHttp 的日志标签；改为核对 R8 类定义 / Manifest / fixture assets，无测试服务类进入 Release。

未验证与协议边界
- 未对真实云端进行发送、停止或定时任务的端到端操作；测试覆盖生产 WS 客户端及 Composable，服务端为本机假服务。
- 未验证实体手机上的输入法、录音 / 附件操作及系统后台回收，本轮只测 SDK 35 模拟器。
- 协议没有消息 id 或队列 snapshot。排队标记根据当前连接的提交 / 回显及 reason:user 顺序维护；重连以服务端历史展示，不猜测旧历史消息是否还在队列中。
- 本轮不增加撤回 / 编辑排队消息，也不持久化运行任务或停止请求。
