实现方式：

1. 简报
   - 删除 0.4 的 BriefCard/BriefBlock/BriefPart 等 JSON 原生模型与卡片组件，只读顶层 cards[].html。
   - 每个 HTML 文档原样从内存返回给独立离线 origin 的 WebView；通过响应头添加 CSP，没有拼接文档或详情页。
   - 加载后读取 document.documentElement.scrollHeight，按 CSS/native 宽度换算高度，上限为屏幕高度的 75%。
   - 长卡片自行滚动；卡片边界保留 v3 圆角、阴影与间距。
   - 只接受主框架的 doudou://prompt?text=，解码一次后发用户消息并切到聊天。其他导航全部消费。
   - 网络、文件、content、弹窗、iframe、下载和权限请求均拦截；允许内嵌 data 图片。没有 JavaScript 原生接口。
   - LazyColumn 按卡片拆成独立 item，只为可见项加载 WebView；缓存高度供占位使用。
     AndroidView onReset 暂停、清回调并供复用，onRelease 销毁；重新绑定会更新 HTML、origin 与按钮回调。
   - 聊天中的简报卡只显示名称和时间，点击跳今日并定位该简报。

2. 模型与权限
   - 设置页增加两项入口，采用大标题、圆角单选列表、每项一行 note 的布局。
   - 选项、当前选择与说明全部来自 GET /api/settings，没有生产模型/权限目录硬编码。
   - PUT 只发送正在更改的字段，以返回结构更新选择；保存失败保留原选择并提示重试。
   - 页面显示“从下一轮开始生效”。假服务中的消耗倍数只是测试数据。

3. 任务详情与续聊
   - 进行中和已完成任务都用服务端 id 打开详情，删除按 label 构造 job id 的做法。
   - 显示任务说明、默认折叠的步骤摘要、Markdown 结果；步骤展开后每项一行。
   - 有简报的结果提供“看简报”，Markdown 中的简报链接也会跳今日，不显示裸路径标记。
   - 底部 POST /api/tasks/<id>/send，校验响应仍是同一 id；失败保留输入，成功后刷新该任务。
   - 运行中的记录由独立 lifecycle.coroutineScope 每 3 秒刷新，不依赖 Compose 渲染时钟。
     页面停止或离开时取消，任务进入终态后停止轮询。加载失败保留已有记录并提供重试。

失败与修复：

- 初期发现轮询读取 Compose 状态/渲染时钟导致静止页面只读一次，已改为用本次响应决定是否继续，
  并使用独立生命周期协程；普通页面实际间隔验证已通过。
- 续聊成功后的原生键盘/焦点操作曾在错误线程触发异常，改由 View 线程执行后通过。
- 冷启动 debug 包的自动设备服务触发过前台服务超时；只在 debug 禁用 BootReceiver，
  工具安装后清理 .checks 测试配置。Release 的设备服务没有改动。
- 模拟器发生过图形驱动中断；切换无窗口运行后最终通过。软件渲染/锁屏或非前台采样不作为性能证据。
- 测试曾在服务端收包后过早断言 UI，或使用被屏幕裁剪的卡片边界判断是否已测量，
  现等待实际 UI 选择/回显、未裁剪尺寸及真正滑出屏幕。早期失败、超时和不完整截图保留在 diagnostics/。
