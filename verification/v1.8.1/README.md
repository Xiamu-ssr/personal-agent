# 1.8.1 聊天和活动验收

消息回执表示云端已经保存用户输入，模型的接收和执行另行完成。待转交输入保存在私有收件记录中；云端启动时按原始消息编号交给 OpenClaw。输入编号同时写入聊天历史，HTTP 重试在云端重启后仍返回原回执。未通过输入校验的请求仍返回错误并保留客户端草稿。

默认加载最近 100 条历史，`after` 补缺口，`before` 向前翻页。重连时使用连接断开前的游标，避免最新一页覆盖中间缺失记录。Mac 一次合并历史并保留顺序；Android 的最新消息位于列表起点，补历史不会触发跨越整段历史的滚动动画。

活动索引只存列表信息，详细过程逐项追加。旧的活动过程及最终结果在启动时迁移，迁移验证逐项核对全部原始事件与结果。工具活动 hook 不再等待 HTTP 记录完成，记录失败不能阻止 `read` 或 `exec`。

已执行：

- 云端 149 项检查及源码检查通过。新增检查覆盖延迟模型确认、收件恢复、跨重启去重、活动迁移和不会阻塞的活动记录。
- 原生 OpenClaw 2026.10.4 的真实 Gateway、合成模型协议检查通过：工具运行期间连续两次插话、同一主会话、一个运行活动、下一轮模型收到两条补充。
- Mac 原生窗口检查通过：千条合成历史一次合并、重连顺序、初始最新位置、向前翻页后的阅读锚点。真实本地 HTTP/WS 收件测试中，模型延迟 20 秒确认、60 秒完成，发送约 11 毫秒清空输入框且只有一条用户气泡。原有 77 项聊天协议断言通过。
- Android API 35 模拟器两项检查通过：千条合成消息直接打开最新位置；往前滚动、插入旧历史、返回底部；真实本地 HTTP/WS 收件后在 2 秒内清空草稿，只有一条气泡，未等待延迟模型。
- 两端正式包完成签名验证。Android 的单元检查、Release 构建通过；Mac 包含 arm64 与 x86_64。

界面与消息测试使用独立数据和本机服务，不向用户主聊天发送测试消息。模型供应商的可用性、服务器长期内存表现与客户端验收分别记录，不能由本机合成测试推断生产错误全部消失。

本机复现：运行 `node verification/v1.8.1/fixture.mjs`（仅 loopback 18771），Android 用 adb 映射相同端口后执行 `ChatLifecycleDeviceTest`。Mac 使用 `mac/tools/compile-check.sh Tests/ChatLifecycleReview.swift` 构建，配置独立 `DOUDOU_DATA_DIR` 后运行。验收截图只含合成内容。
