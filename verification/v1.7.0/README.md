# 1.7.0 资源、长会话与定时活动验收

## 实现

- Mac 聊天用 `NSTableView` 复用可见行，移除整段 SwiftUI 消息布局和旧滚动观察器。保留历史阅读位置、新消息提示和回到底部；缩放时按消息锚点保持正在阅读的条目。
- 资源目录统一为 `data/library/sites/`、`documents/`、`media/`。Mac、Android 均有全部、站点、文档、图片、视频、音频筛选。
- 索引按实际文件变化失效；预览按站点修订生成并落盘。客户端保留列表、合并重复请求，缓存按服务器和账号隔离；内容更新后条件重验证。
- 定时活动记录安排编号与最近执行结果。心跳、Goal 等主会话空闲后执行；Feed、Idea 独立 Session 更新共享文件。删除自动截取后台结果并拼进主会话的队列，完整结果通过活动编号读取。
- 内容发布直接校验 App 所读的文件；Goal 状态、字段和业务目录由同一内容契约生成。没有第二份内容数据库。
- 所有模型统一设置 272000 上下文、128000 最大输出。原生 OpenClaw 执行压缩和记忆 flush，保留主 Session。
- 网关断线后按原 runId 查询完成结果，不重新发送执行请求。不确定结果单独标识。
- 图片、视频、音频按 MIME 与扩展名直接展示；MP4 H264/AAC 与 MP3 已实际播放。预览继续使用轻量图，正式 HTML 导出单独生成完整 PNG。

`mac-performance.json` 是同一合成工作负载下的 45 秒对照：500 条长消息、窗口缩放和新消息。旧代码末尾 footprint 172.38 MiB，修改后 58.84 MiB；峰值 CPU 分别为 93.2% 和 20.6%。这是进程 CPU 和 physical footprint，不是能耗指标。没有完整复现用户现场的 1.7 GB，不能宣称所有内存问题均已根除。

本地界面与截图全部使用合成账号和文件。模拟器结果不代表 OPPO 真机；本地合成模型不代表外部模型服务。正式安装包与生产部署结果另记。Mac 使用本地签名，未经 Apple 公证。

## 正式安装包与生产

签名后的正式 DMG 已挂载并运行：实际加载 1000 条合成消息，手动操作历史滚动、窗口缩放、资源筛选，以及发送/接收消息。缩放前后保持同一条第 993 条消息。连续观测 180 秒，进程存活，physical footprint 峰值 179.74 MiB，末值 126.81 MiB；期间短时 CPU 峰值 100.7%，中位数 2.6%，没有观察到持续卡死。完整采样见 `mac-formal-dmg.json`。这不能替代真实用户长期使用。

正式 Android APK 已在模拟器安装，版本号 1.7.0、versionCode 26，签名证书与上一版相同。Mac 为 arm64/x86_64 通用二进制，严格签名、DMG 校验通过。

云端已升级 1.7.0。首次迁移因备份目录执行权限被检查阻止，自动恢复了原服务；第二次先备份再迁移成功。模型供应商、设置和连接器的 16 个受保护文件未改变；所有聊天消息编号、记忆文件、二进制资源和原生主 Session 均保留。旧资源目录和后台结果拼接队列已删除。

真实资源库的六个站点预览全部通过；索引条件请求返回 304。生产 HTML Cookie 仍为 Secure 与 /agent 路径。使用独立原生 Session 完成一次真实模型请求，耗时约 26 秒，主 Session 未用于诊断。见 `deployment.json` 与 `production-check.json`。
