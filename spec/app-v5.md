# 豆豆 0.6 · 简报更密更好看、皮肤、健康页、任务历史、主动跟进、Wind

在 `app-v4.md` 的基础上改。没提到的照 v4。2026-10-12 用户定的。

用户用 0.5 一天后的结论：整体流畅，但简报「太宝宝了」，卡片里出现滚动条，一个耳机比价拆成 5 张卡片；字体颜色像老安卓；提示词有过拟合。

## 一、简报：卡片就是卡片

**卡片不再内部滚动**
- 卡片高度完全跟内容走，App 里没有内部滚动、没有滚动条，整页一起上下翻。
- 每张卡片至少一句结论，最多约 1.5 屏（画板上约 960px）。超过就由云端退回让豆豆精简，App 不截断。
- 横向手势不被卡片吃掉（见「四、横滑」）。
- Mac 和手机同一种排法：Mac 的今日页是一列，宽度保持手机比例（约 420–480pt），居中，不做两套布局。

**一个主题一张卡片**
- 一个主题只占一张卡片。比如「耳机比价」是一张卡片，里面一个对比表；不再拆成 5 张。
- 晨报、晚报这类综合简报：第一张总览，之后每个主题一张，最多 6 张。
- 单一主题的简报（调研结果、比价、进度）通常就 1 张。

**更密的组件**（学 Today AI，云端基础样式提供，两端一致）

| 组件 | 长什么样 |
|---|---|
| 分类 chip | 顶部小字「分类 · 主题」，如「出行 · 国庆返程」 |
| 判断标题 | 一句话结论，大字 |
| 日期条 | 横排 5–7 天，每天标星期和日期；节假日、调休上班、节气用小标记 |
| 状态格 | 横排 3 格：小标题、大数字或短词、一行说明，可标好/注意/提示色 |
| 步骤 | 编号步骤，每步一行字 + 状态 chip（已完成 / 进行中 / 待做），可带进度条 |
| 对比 | 两到三列对比：每列一个选项，逐行比较，推荐的那列高亮 |
| 时间线、列表、灰底提示、大数字指标 | 保留 0.5 的 |
| 按钮行 | 一张卡片最多 2 个按钮，主次分明；点了把按钮上的话发给豆豆 |

- 基础样式跟着 App 皮肤走（见「七、皮肤」）：App 加载卡片时告诉卡片当前皮肤，基础样式里的颜色和字体随之切换。豆豆写的配色变量在每套皮肤下都有对应版本，深色皮肤下卡片也是深色。

**晨报内容**
1. 总览：日期 chip 带农历，如「10月12日 周一 · 农历九月初三」；一句话判断今天最要紧的事；一条日期条，标出未来几天的节假日、调休、节气。
2. 今天：日程和天气。
3. 最近：前一两天的行程和豆豆帮着做过的事（日历、聊天记录、日记里有的）。
4. 跟进：之前问过、还没收尾的事，写当前进度和下一步，用步骤组件（见「二、主动」）。
5. 消息：只挑要用户处理的。

读不到的照实写原因。没有内容的部分整张省掉，不写空卡片。

**豆豆自己先看一眼**
- 新增「页面截图」能力：豆豆可以把自己写的简报或站点按手机宽度截一张图看。
- 简报和站点交付前先截图检查：有没有挤、溢出、空白、颜色看不清。只用于检查豆豆自己的页面，不用来上网。

**校验**：卡片数量 1–6、每张高度估算不超过 960px、外部资源、文件大小，照旧由云端在写完后检查，用中文告诉豆豆哪里不对。

## 二、系统提示词：去掉过拟合，加上「主动」

**只留产品约定**
- 业务提示词只写豆豆这个产品通用的规则：目录约定、数据来源、记忆规则、对外动作、诚实、时间、主动。
- 个人口味挪出去：
  - 「靠谱、话少、偶尔幽默」只在默认角色设定里。
  - 「结论先行；推荐只给一个答案和硬理由；不写开场白和客套」写进默认角色设定的「说话习惯」。用户的线上角色文件一次性补上这一段（已有就不动）。
- 用户以后对说话方式的要求，照旧写进 `feedback/`，由豆豆每次读。

**主动**（新增一节）
- 目标是让用户觉得豆豆想在了前面，但不唠叨。
- **记住没收尾的事**：用户问过、托过、在等结果的事（等快递、比价没买、计划出行、在做的家务进度），记进跟进清单 `data/follow-ups.md`。每条写：什么事、哪天说的、现在到哪一步、下一次什么时候提。事情了结就删掉。
  - 跟进清单不是记忆：它记的是进行中的事，不受「只记事实」约束，也不进总档。
- **在合适的时候提起**：晨报的「跟进」一节、或用户下次聊到相关话题时，顺手带上进度和建议的下一步。同一件事用户没回应，不连续两天提。
- **先查再问**：能从记忆、设备、连接器、网上查到的，先查，不问用户。查不到、且答案会改变做法时才问，一次问完。
- **不唠叨**：一条消息里最多带一件用户没问的事；用户说「不用管了」的，从跟进清单删掉，不再提。

**每条消息附带的时间信息**加上：农历日期、节气（当天是节气时）、今天是工作日 / 周末 / 法定节假日 / 调休上班，以及未来 7 天里的节假日和调休。数据用开源的中国节假日日历，随版本更新，不靠模型记。

## 三、聊天的滚动

- 往上翻看历史时，右下角出现「回到底部」按钮；有新消息时按钮上显示条数。点一下滚到最底。
- 点输入框、弹出键盘时：
  - 本来就在底部，就跟着停在底部；
  - 正在往上翻看，就停在原地，不跳。
- 发送消息后滚到底部。
- 正在流式输出时，只有在底部才跟随；用户往上翻了就不再自动拉下去。

## 四、横滑

- 手机上左右滑动切换：
  - 今日页先在「简报 ↔ 站点」之间切；已在最边上再滑，切到相邻页签。
  - 没有分段的页面直接切相邻页签。
  - 页签顺序：聊天、今日、任务、记忆。
- 卡片里的横向内容不吃这个手势；输入框、横向滚动的列表和对比表除外。
- Mac 上触控板双指横滑切「简报 ↔ 站点」，页签用侧栏切。

## 五、任务

**任务列表**
- 分组：进行中、今天、近 7 天、更早。更早的往下翻继续加载，不限 50 条。
- 云端把服务器上已有的旧任务记录补进来（0.5 之前的后台任务，现在列表里看不到）。任务名取当时交代的那句话。

**任务详情 = 聊天界面**
- 打开任务就是一个和主聊天长得一样的对话页：
  - 第一条消息是主会话交给它的任务说明，标「豆豆交代的」。
  - 中间是豆豆的步骤，和主聊天里的工具行一样，默认折叠。
  - 结果是豆豆的回复。
- 底部是和主聊天同一个输入框，能发文字、图片和文件。
- 云端重启后，旧任务也能接着聊。

## 六、记忆 · 健康页

记忆页点「健康」，打开健康页，不再显示 JSON。照 Today AI 的健康页做。

- **顶栏**：标题「健康」，右边一个云同步按钮：点一下马上从手机同步一次，旁边显示上次同步时间。
- **今天**：2×2 小格：睡眠、静息心率、心率变异性、步数。
  - 每格是今天的数值。
  - 下面画近 7 天的小图：睡眠和步数用柱，心率和心率变异性用线。
  - 没有数据显示「--」。
- **周报**：历次健康周报的列表，每行是日期范围和一句话总结，点开看那份简报的卡片。不限 7 天。
- **健康记录**：`health` 分类下的记忆文件，两列小卡片，显示标题、更新日期、前两行预览，点开是记忆文件页。
- 「新」标记保留。

**数据从哪来**
- 云端每 3 小时检查一次：手机在线、开了健康，就读最近 7 天的睡眠、步数、静息心率、心率变异性，存成按天的健康数据。打开健康页、点同步按钮时也读一次。
- 这一步由云端直接向手机要数据，不经过模型，不花 token。
- 健康数据豆豆可以读（写简报用），不能改。原来健康周报顺手写的那份最新指标文件撤掉，已有的删掉。

## 七、皮肤

**设置 → 皮肤**，三套，点了马上换，两端各自保存。

| 皮肤 | 气质 | 底色 / 卡片 / 文字 | 强调色 | 字体 |
|---|---|---|---|---|
| 银蓝（默认） | 清爽、克制 | 冷白灰 / 白 / 深灰蓝 | 银蓝 + 香槟金点缀 | 系统黑体；标题加粗、字号拉开层次 |
| 纸墨 | 安静、有书卷气 | 米白纸色 / 暖白 / 墨黑 | 朱砂红，少量 | 标题用宋体（系统自带衬线），正文黑体 |
| 夜幕 | 沉稳、夜里不刺眼 | 近黑 / 深灰 / 柔白 | 薄荷青 + 琥珀 | 系统黑体，字重偏轻 |

- 皮肤管整个 App：底色、卡片、文字、图标颜色、输入框、页签、按钮、聊天气泡，以及简报卡片的基础样式。
- 排版统一升级：标题和正文的字号层次拉开，行距更松，数字用等宽数字，圆角和阴影更轻。不要像老安卓：去掉粗边框、去掉大色块按钮和默认灰阶。
- 不跟随系统深浅色；用户选哪套就是哪套。

## 九、连接器 · Wind AI

- 目录里新增「Wind AI」（万得金融数据）。用户只填一个 API Key，在 Wind AI 金融市场网站的用户中心申请。
- 连上后豆豆能查：股票、基金、指数、债券、宏观经济、公告研报、量化分析数据。这是 Wind 官方开放的 7 个数据服务，一个 Key 全通。
- 密钥只在云端：豆豆通过连接器调用，看不到 Key。
- **技能一起装**：连上时，云端从 Wind 官方的技能仓库下载技能，改成通过连接器取数，装给豆豆。默认装 3 个核心技能：数据路由、找技能、Wind Alice 分析助手。其他几十个分析技能由「找技能」按需取用，不常驻上下文。
  - 断开连接器时一起卸掉，升级时重新拉取。
  - 夜间整理不动这些技能。
- **连接器 = 工具 + 技能**：工具负责取数，技能教豆豆怎么用这些数据做分析。以后其他连接器有官方技能的，也这样一起装。

## 十、浏览器（下一版，不在 0.6）

用户要的是一台真正的浏览器：

- 和 Mac 上的 Chrome 一样有窗口；
- 网站看不出是机器人；
- 能记住账号和密码；
- 学 Today AI「云电脑 + 独立浏览器」的做法。

**为什么不在 0.6**：现在的云主机只有 2 核、不到 2G 内存，豆豆本体已经用掉大半。再跑一个带窗口的 Chrome 和远程画面，会把豆豆挤垮。

**打算**
- 单独开一台云电脑（约 4 核 8G），专门跑豆豆的浏览器，和豆豆本体分开。
- 用正版 Chrome，开窗口运行，不是测试模式；账号、密码、Cookie 一直保留，用 Chrome 自带的密码管理。
- 豆豆像人一样看画面、点、打字。
- 遇到登录、验证码，App 里能打开远程画面，用户自己接管点一下，再交还给豆豆。
- 云上的网络出口有些平台会多要一次验证，用户接管一次后通常就记住了。
- 在这之前，Mac 在线时豆豆照旧用 Mac 里的「豆豆浏览器」，登录状态是保留的。
- 开机器要花钱，下单前单独问用户。
