# 豆豆 App v3（0.4）· 今日、任务、记忆、豆豆、设置的改版

在 `app-v2.md` 的基础上改。没提到的页面、接口、视觉规则都照 v2。两端还是同一个产品的两种布局。0.3 已上线的排队消息、忙碌提示、后台任务条、闹钟灰字、连接应用页面都保留，协议见 `cloud/docs/app-protocol-tasks.md`。

参考：Today AI 安卓录屏 `personal-agent-sim/refs/today-ai-android-walkthrough.mp4`。学它的信息层次和卡片样式，配色和字体继续用 v2 第四节的银蓝 + 香槟金。示例数据不要照抄。

总原则：**列表里直接把内容看完，少一层跳转**。所以每个页面都去掉重复的文字、日期行和提示语。

## 一、简报改成结构化卡片

### 1. 文件
简报从 HTML 改成 JSON，路径是 `data/briefs/<YYYY-MM-DD>/<任务名>.json`。App 用原生组件画卡片，没有详情页。不兼容旧格式：上线时把现有的 `.html` 简报一次性迁移掉，App 和接口只认 JSON。

```json
{
  "v": 1,
  "name": "晨报",
  "time": "2026-10-11T07:36:00+08:00",
  "cards": [
    {
      "chip": "10月11日 周日",
      "title": "今天只有一件硬事：下午三点前交周报",
      "summary": "上午空着，适合先把周报收尾；晚上有雨。",
      "blocks": [
        { "type": "timeline", "items": [ { "when": "15:00", "label": "交周报", "text": "发给王经理" } ] },
        { "type": "tiles", "items": [ { "title": "天气", "text": "多云转小雨 18–24°", "tag": "带伞", "tone": "warn" } ] },
        { "type": "metrics", "items": [ { "label": "睡眠", "value": "6.5", "unit": "小时", "delta": "-0.8" } ] },
        { "type": "list", "items": [ { "text": "快递已到驿站", "meta": "取件码在短信里" } ] },
        { "type": "note", "text": "日历暂不可读：手机离线" }
      ],
      "action": { "label": "排一下今天的顺序", "prompt": "帮我把今天的事排个顺序" }
    }
  ]
}
```

| 字段 | 规则 |
|---|---|
| `cards` | 1–5 张。第一张是总览，`chip` 写日期；后面每张一个主题，`chip` 写分类，比如「采购 · 收口」 |
| `title` | 一句话结论，不超过 28 个字 |
| `summary` | 可选，不超过 80 个字 |
| `blocks` | 可选，每张最多 4 个。`timeline` 最多 4 项，横排；`tiles` 2–3 项，小卡片 + 彩色标签；`metrics` 最多 4 项，数字大字；`list` 最多 6 项；`note` 灰底一行，写暂不可读的原因 |
| `tone` | `ok` / `warn` / `info`，只控制标签颜色 |
| `action` | 可选，一个按钮。点了把 `prompt` 当用户消息发到聊天并切到聊天页 |

- 不认识的 `type` 跳过不画。缺字段就不画那一块，不报错。
- 文字里不用 emoji，不放链接和 Markdown。

### 2. 云端
- **校验**：主会话和 fork 用 Write / Edit 写 `data/briefs/**/*.json` 后，PostToolUse 解析并按上表校验。不通过就把中文错误回给模型，让它改对，比如「cards[1].title 超过 28 字」。
- **新接口** `GET /api/briefs?days=7` → `{items:[{date, name, time, path, brief}]}`。按时间倒序，`brief` 是解析好的 JSON。这样 App 一次请求就能画完列表。
- **卡片消息**：`job.done` 卡片带上 `path`。聊天里的简报卡片显示 chip + title + summary，点了切到「今日」并滚到那份简报。
- **提示词**（`spec/prompts/system-prompt.md`）：
  - 产出物表里的简报一行改成 JSON 格式，附上最小示例和字段限制。不要把整张 schema 都贴进去。
  - 三个简报任务的 prompt（`schedule.json` 里的晨报、晚报、健康周报）去掉「写完最后一句只输出卡片标题」，改成「按简报格式写 JSON」。
  - 完成通知到了以后，主会话觉得哪里不满意可以接着改。目的是简报质量，不限制它。

## 二、站点缩略图

- **缩略图由 App 自己生成**：在不可见的 WebView 里按手机宽度加载 `index.html`，截首屏，按「路径 + mtime」缓存。加载失败就显示渐变底 + 站点名首字。
  - 不用豆豆提供图片，那样不稳定。
  - 也不在云端装无头浏览器，太重。
- **标题和简介**读 `index.html` 的 `<title>` 和 `<meta name="description">`。提示词第 116 行补一句：做站点时写好这两项。
- `/api/tree?dir=data/sites` 已经有 mtime，不需要新接口。

## 三、页面改动

### 聊天
- 顶部胶囊只留头像 + 「豆豆」+ 状态点：绿 = 在线，灰 = 离线，金色呼吸 = 忙。
- 删掉「在线 · 本机已接入」和工具提示，忙碌提示已经在输入框上方了。
- **排队消息可以撤回和修改**：长按排队中的气泡，出现「撤回」「修改」。
  - 排队是云端自己做的（`turnQueue`），轮到时才交给 SDK，所以不需要 SDK 支持。
  - `user` 事件带上 `id`。新增 WS 消息 `{t:"unqueue", id}` 和 `{t:"edit_queued", id, text}`，回包 `queue_update {id, state: "removed" | "edited" | "too_late", text?}`。已经开始处理的回 `too_late`，App 提示「豆豆已经在看这条了」。
  - 聊天记录改成轮到时再写入 `chat.jsonl`。撤回的消息不进历史，修改的写最终文本。

### 今日
- 大标题「今日」下面是分段 **简报 · 站点**，默认简报。删掉日期行和「最近」「站点」小节。
- **简报**：
  - 数据来自 `/api/briefs`，按时间倒序。
  - 按天分隔：「今天」「昨天」「10月9日 周五」。
  - 每份简报上方一行小字「7:36 晨报」，下面是它的卡片。
  - 空状态「今天还没有简报 · 晨报 7:30」。时间从 schedule 里取。
- **站点**：两列网格。每张卡上半部是缩略图，下面是标题、一行简介、「更新于 …」，点开 WebView。

### 任务
- 分段只有 **任务 · 定时**。删掉「为你推荐」和「想加或改定时任务…」提示。
- **任务**：进行中和已完成合成一个列表。
  - 进行中的排最上面：转圈图标、已运行时长、单独停止。数据和 0.3 的后台任务条一致，以服务端为准。
  - 已完成的按「今天 / 近 7 天 / 更早」分组：标题、时间、成功或出错。有简报的点了跳到今日，有文件的点开 WebView。
- **定时**：同 v2。

### 记忆
1. 顶部大卡「我对 {称呼} 的了解」：
   - 内容取 `总档.md` 的前几行，用较大的字号。
   - 底部「查看全部」打开完整总档，`→ 指针` 照 v2 渲染成标签。
   - 卡片角上一个金色小徽记。
2. 「全部」小节：
   - **健康**卡：通栏，里面 4 个小格（睡眠、静息心率、步数、心率变异性），数字大字，单位小字。
     - 数据来自 `data/memory/health/latest.json`：`{updated, metrics:[{key, label, value, unit}]}`，由健康周报顺手写。
     - 没有数据时显示「--」，并在卡片底部用小字写「还没有健康数据」。
   - **语音笔记**卡：通栏，显示 `voice-notes` 分类的条数和最近一条的时间。没有就写「按住说话发的语音笔记会出现在这里」。
   - **其他分类**：两列「文件夹」样式卡片，卡片上沿带一个页签形状。卡上是中文名、N 项、最近更新的文件名。只显示有文件的分类，顺序同 v2。
3. 字体层次参照 Today AI：大卡标题 22 粗；卡内正文 15，行高 1.6；数字 24 粗。

### 豆豆
- **头像**：上半屏通栏，柔和、带梦幻感的插画。下面是名字「豆豆」和一行「从 2026年9月24日起陪伴 {称呼}」。日期取 `firstChat`。
  - 头像可以换：轮廓选 豆子 / 女生 / 男生 / 猫，配色选 晨雾蓝 / 暮光金 / 薄荷 / 樱粉。
  - 只改外观，不改豆豆的人设和提示词。
  - 头像用代码绘制：剪影里填天空渐变 + 柔光 + 云层，两端用同一套参数。不放位图资源，体积小，两端看起来也一致。
- **选择存在云端**，两端同步：新接口 `GET /api/profile` → `{avatar:{shape, palette}}`，`PUT /api/profile` 写入 `system/app-profile.json`。默认是豆子 + 晨雾蓝。
- **日记**改成便签：
  - 横向滑动，每张一种浅色纸，按星期轮换，轻微倾斜 ±1.5°。
  - 左上角是日历小块：上面英文星期缩写，下面是大号日期数字，比如 SUN / 4。
  - 下面是标题和 3 行摘要。
  - 「查看所有日记」进两列便签网格，点开看详情（Markdown）。
- 「豆豆的设定」一行保留。

### 设置

## 四、本机能力（0.4 重排）

端侧就是挂在设备上的连接器。云端调用离线设备时，返回「设备离线」，豆豆如实告诉用户。

### Mac：命令行 + 操作电脑 + 浏览器

| 能力 | 名字 | 说明 |
|---|---|---|
| `shell` | Mac 命令行 | 以用户身份在 zsh 里执行命令。参数 `{command, cwd?, timeout?≤300}`，返回 stdout、stderr、退出码，输出超过 20k 字就截断。电量、剪贴板、打开网页、快捷指令、当前应用、读写文件都用它，不再单独列能力。 |
| `folder_desktop` / `folder_documents` / `folder_downloads` | Mac 桌面 / Mac 文稿 / Mac 下载 | macOS 对这三个文件夹单独做了隐私保护，命令行默认读不到。打开开关 = 触发系统授权。授权后命令行就能访问这三个文件夹，所以这三项本身没有工具，只是授权开关。 |
| `computer_use` | 操作电脑 | 截屏 + 鼠标键盘。工具：`screenshot({display?})` 返回图片；`click({x,y,button?,double?})`、`type({text})`、`key({keys})`、`scroll({x,y,dx,dy})`、`drag({from,to})`。需要「屏幕录制」和「辅助功能」两个系统授权。 |
| `browser` | 浏览器 | 操作用户自己的 Chrome，用的是同一份登录状态和 Cookie。豆豆 Chrome 扩展通过本机 WebSocket 连到豆豆 App，用 `chrome.debugger` 执行操作。工具：`tabs()`、`open({url})`、`snapshot({tab})` 返回带 ref 的页面结构、`click({tab, ref})`、`type({tab, ref, text})`、`screenshot({tab})`、`close({tab})`。扩展第一次需要用户手动安装（开发者模式加载）。 |
| `notify` | 发通知 | 保留原生：通知要显示成「豆豆」发的。 |
| `calendar_events` | Mac 日历 | 保留原生：日历权限挂在 App 上，命令行读不到。 |

- 删掉的旧能力：`battery`、`clipboard_read`、`clipboard_write`、`open_url`、`frontmost_app`、`shortcuts`、`folder`。不做兼容。
- **截图要回传给模型**：设备协议要支持图片结果。设备返回 `{image: base64, mime}`，云端转成 MCP 的 image 内容。
- **固定签名**：TCC 授权是绑在签名上的，ad-hoc 签名每次升级都会丢授权。所以在本机建一个专用钥匙串和自签名代码签名证书（放 `~/.personal-agent/signing/`），`build.sh` 用它签名。这样屏幕录制、辅助功能、文件夹授权都能跨版本保留。

### 安卓（没有命令行，保留细分能力）

| 能力 | 变化 |
|---|---|
| `battery`、`location`、`calendar_events`、`sms`、`clipboard_write` | 不变 |
| `notify` | 增加可选参数 `url`，点通知时打开这个链接 |
| `open_url` | **删掉**。安卓后台不能直接打开页面，原来只是发一条通知，和 `notify` 重复；而且由豆豆在手机上弹出页面太打扰。 |
| `health` 运动健康 | **新增**。优先读 Health Connect（系统级接口，各家厂商的健康 App 同步进来就能读）：步数、睡眠、心率、心率变异性。Health Connect 不可用或没有数据时，用系统计步传感器（`TYPE_STEP_COUNTER`）兜底，只有步数。参数 `{from, days}`。 |

### 授权：能一次开就一次开
- 首次引导和「本机」页顶部各有一个「一键开启」按钮。
- **安卓**：把所有运行时权限放在一次 `requestPermissions` 里申请，系统会连续弹出。Health Connect 是单独一页，随后打开。
- **Mac**：系统不允许一次性申请。按顺序走：通知 → 日历 → 桌面 / 文稿 / 下载 → 屏幕录制 → 辅助功能。屏幕录制和辅助功能需要用户在系统设置里打开，App 直接跳到对应页面，并轮询授权结果。
- 每项能力仍然有自己的开关，可以单独关。

## 五、云端行为（不改 UI，也写进来）

- **定时简报**：
  - 闹钟消息里写明「用 Agent（fork，后台）派出去」，运行层要求 schedule 回合第一个工具必须是后台 fork。被拒 3 次就放开，不会卡死。
  - 2026-10-11 17:36 的线上测试第一次就派出了 fork，没有被拒。
- **上下文改成 200K 窗口**（用户 2026-10-11 决定：100K 压缩太频繁）。
  - CLI 窗口 200K，给输出留 20K、给摘要留 13K，所以输入约 167K 时触发压缩。
  - 代价：超过 100K 的请求进 Haiku 5.5 的高价档。
  - 以前在 95K 时压缩成功过 3 次：18.4 万→6.8K、9.5 万→6.0K、9.8 万→4.6K。
