# 豆豆 0.5 · HTML 简报卡片、切换模型、任务续聊、保留 Claude Code 内置提示词

在 `app-v3.md` 的基础上改。没提到的照 v3。2026-10-11 用户定的。

## 一、简报：每张卡片是一段 HTML

0.4 的 JSON + 原生组件撤掉。像低代码一样限制了表达，不够灵活。

**用户看到的**
- 一份简报由 1–6 张卡片组成。每张卡片是一段 HTML，App 用 WebView 渲染。
- 卡片高度跟内容走，最高不超过屏幕的 75%，超出部分在卡片内部滚动。
- 列表里能一眼看出一张张卡片，可以上下翻。
- 卡片点不进去，没有详情页。
- 卡片里可以有 CSS 动画。
- 卡片里可以有按钮：`<button data-prompt="帮我把今天的事排个顺序">排一下今天的顺序</button>`。点了把这句话当用户消息发到聊天，并切到聊天页。

**豆豆怎么写**
- 文件是 `data/briefs/<YYYY-MM-DD>/<任务名>.html`。每张卡片是一个顶层 `<section class="card">`。可以带一个 `<style>`。
- 画板：宽 360px（App 实际在 320–480px 之间自适应），每张卡片高度不超过 560px。
- 云端提供一套基础样式，统一注入，两端一致：
  - 字体、圆角、阴影、间距；
  - 4 套推荐配色，用 CSS 变量：银蓝 + 香槟金（默认）、晨雾、薄荷、暮光；
  - 常用小组件的 class：日期 chip、一句话标题、摘要、横排时间线、小卡 + 彩色标签、大数字指标、列表、灰底提示、按钮。

  豆豆可以直接用这些 class，也可以自己写样式。
- 不加载任何外部资源。图片只用内联 SVG 或 data URI。WebView 禁止联网。
- **简报写法**是一段单独的提示词：画板尺寸、配色、组件、UI 设计技巧（第一张是总览、一句话结论、数字大字、少写长段落、留白）。它附在晨报、晚报、健康周报的定时消息后面一起发，不写进系统提示词。
- 写完后云端校验：卡片数量、高度估算、外部资源、文件大小。不通过就用中文告诉豆豆哪里不对，让它改。
- 已有的 JSON 简报一次性迁移成 HTML，不做兼容。

参考：Today AI 录屏 `personal-agent-sim/refs/today-ai-android-walkthrough.mp4`，前 9 秒是简报页。截好的帧在 `personal-agent-sim/refs/frames/`（`t2`–`t8.png`、`brief-strip.png`）。

## 二、系统提示词：保留 Claude Code 内置的

- 以前我们的系统提示词把 Claude Code 内置的整个替换掉了。现在改成：保留内置提示词，把豆豆的业务提示词接在后面。
- 业务提示词里删掉简报格式（挪到「简报写法」）。只留一句：简报放在 `data/briefs/`。
- **压缩**：完全用 Claude Code 内置的，不再追加我们自己的压缩要求。
- **定时消息**：到点后把定时任务的提示词原样发到主会话。「放到后台做」这件事由运行层处理，不让提示词关心技术细节。

## 三、模型和权限：在 App 里选

**设置 → 模型**（学 Today AI，每个模型标消耗倍数）

| 显示名 | 模型 ID（ZenMux） | 每百万 tokens：输入 / 缓存读 / 输出 |
|---|---|---|
| Claude Haiku 5.5（默认） | `anthropic/claude-haiku-5.5` | $0.1 / $0.01 / $0.5；输入超过 100K 后都 ×5 |
| MiMo V2.6 Pro | `xiaomi/mimo-v2.6-pro` | $0.435 / $0.0036 / $0.87 |
| GLM 5.3 FlashX | `z-ai/glm-5.3-flashx` | $0.375 / $0.075 / $1.25 |

- 换了以后，从下一轮起全部走新模型，包括主会话、后台任务、夜间整理、补读，以及自动审批的判断。
- 推理强度都是 max。
- 上下文统一 200K 窗口，输入约 167K 时压缩。
- 选择存在云端，两端同步。

**设置 → 权限**（放在模型旁边）
- 「自动」（默认，`auto`）：不问用户，Claude Code 自带的判断会拦下危险操作，拦下的结果告诉豆豆。
- 「完全放行」（`bypassPermissions`）：什么都不拦。
- 两种模式都不会向 App 弹请求。

## 四、任务可以续聊

- 任务页点一个任务，打开它的对话记录：任务说明、豆豆做了哪些步骤（默认折叠）、最终结果。
- 底部有输入框，可以接着聊。接着做的事带着这个任务原来的完整上下文，仍然在后台跑，完成通知照旧。
- 进行中的任务也能打开看，进度实时刷新。

## 五、Spec（`spec/spec.yaml`）

- 提示词区只放 6 条：系统提示词、晨报、晚报、健康周报、夜间整理、简报写法。
  - 每条只写触发条件（比如「每天 7:30」）和渲染好的提示词全文。
  - 不写文件名、行号、代码、运行层的包装文字。
- Claude Harness 节点写清楚：可选模型、推理强度、权限模式、上下文窗口和压缩、系统提示词接法、压缩用内置的。
- 整个 spec 去掉代码细节和小字。spec 是对齐产品用的，不是代码说明书。
